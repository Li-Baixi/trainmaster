# 架构说明（供 AI 维护参考）

> 本项目由 AI（Claude Code）全权维护，用户无代码能力。本文记录架构决策与约定，修改代码前必读。

## 总览

纯静态、无构建的中文 PWA。vanilla JS（ES modules）+ hash 路由。托管 GitHub Pages（子路径 `/trainmaster/`，全站相对路径）。数据 100% 存手机 IndexedDB（虚拟 md 文件系统），可导出/导入真实 .md。AI 调用经用户自部署的 Cloudflare Worker 透传（解决 CORS）。

```
iPhone Safari PWA
   │  fetch(workerUrl + /v1/chat/completions)
   │  headers: Authorization(user key) + X-Api-Base(provider baseUrl)
   ▼
Cloudflare Worker（worker/proxy.js，无状态透传 + CORS + Origin 白名单）
   │
   ▼
DeepSeek / 任意 OpenAI 兼容服务商
```

## 目录与模块

```
js/
  main.js        入口：boot（开DB/persist/SW/首跳向导）
  router.js      hash 路由 #/today|chat|plans|profile|records|settings|onboarding
  db.js          IndexedDB（trainmaster v1：files/messages/meals/settings 四仓）
  vfs.js         虚拟文件系统（files 仓），路径约定见下
  settings.js    配置高层 API（providers/workerUrl/ctxPrefs/nickname…）
  ai/client.js   OpenAI 兼容客户端：chatStream(SSE)/chatOnce(降级)/testProvider/testWorker
  ai/context.js  上下文组装（五段式 system prompt + 字符预算）+ extractFence/stripFences
  ai/image.js    压缩（EXIF 修正/长边1280/JPEG0.8）、缩略图、视觉消息构造
  services/      onboarding(问卷+两次生成) / chat / plans(版本归档) / meals(识餐) / logs(当日md) / backup(导出导入)
  ui/            markdown.js(渲染入口) / components.js(el/toast/modal) / mealcapture.js(识餐全流程) / pages/*
```

## 数据：虚拟路径约定（files 仓 keyPath=path）

```
profile.md                       个人档案（唯一真源）
plans/current.md                 当前计划（头部有 <!-- 生效于… --> 注释）
versions/plans/YYYY-MM-DD_HHMM.md   计划历史（应用新版时归档）
versions/profile/…               档案历史
versions/imported/<时间>/<path>  导入时被覆盖内容的备份
logs/YYYY-MM-DD.md               当日日志（对话段 + 餐食段 + ```meal json 围栏）
```

**双写原则**：messages/meals 仓是 UI 真源（快速渲染），md 是导出真源；写仓成功后追加 md，md 失败仅 toast 不阻塞；导入时从 md 的 meal 围栏重建 meals 仓。

**导出文件名**：路径 `/` 替换为 `__`（如 `plans__current.md`），导入时反向还原；`log__日期` 特判映射到 `logs/日期`。

## AI 协议（context.js）

五段式 system prompt：人设 → 档案(≤2500字) → 计划(≤3500字) → 最近N天动态(每天≤900字) → 输出协议。对话历史最近 20 条、每条≤4000字，**只有最近一条带图的消息保留图片**。

围栏协议（extractFence 宽松匹配 ```tag 开头）：
- ```plan — 新计划全文（确认后 applyNewPlan 整体替换+归档）
- ```mealjson — 识餐结构化结果（失败可手动填）
- ```profile — 向导生成的档案

**路径拼接约定**：浏览器请求 Worker 的 `/v1/chat/completions`，Worker 去掉 `/v1` 前缀拼到 X-Api-Base 后面。所以 provider.baseUrl 填"不含 /v1"的地址（DeepSeek: https://api.deepseek.com）；OpenAI 官方则填 https://api.openai.com/v1。

## 关键维护约定（必守）

1. **改任何前端资产必须递增 sw.js 顶部的 VERSION**，并把新文件加进 PRECACHE（否则用户端缓存不更新）
2. vendor/ 里的库版本固定，文件头有版本注释；升级=下载新版覆盖
3. 所有用户输入/AI 输出渲染 HTML 必须走 ui/markdown.js（DOMPurify）
4. AI 落盘（计划/档案）必须经过用户确认（提案卡/确认框）
5. API Key 永不出设备：不写进导出、不发给 Worker 以外的任何地方
6. UI 全中文；面向无代码能力用户，错误提示要告诉他去哪里点
7. 模型名是会变的（DeepSeek 视觉模型当前默认 deepseek-flash）：设置页可改 + 测试连接兜底，升级模型时改 settings.js 里的默认值即可

## 本地开发与验证

# 浏览器开 http://localhost:8000

注意：ES modules 不能用 file:// 直开；SW 只在 https（或 localhost）注册；本地联调需 Worker 的 ALLOWED_ORIGINS 含 http://localhost:8000。

## 已知取舍

- iOS 无 File System Access API → md 存 IndexedDB，靠导出/导入闭环
- md 日志是追加式（append-only），删除餐食只影响 meals 仓与汇总，不改历史 md
- 长对话上下文靠预算截断（保头/保头尾），不做 embedding/检索
